# F2.3 Macros

**Phase** 2 · **Size** M · **Prototype** yes · **Requirements** FR-6, FR-9 · **Depends on** F0.4, F0.5

## Summary
Macros are calculated on the server from catalog nutrition data, never by the model. There's one shared function, used by generation (F2.2), editing (F3.2) and the `recompute-macros` endpoint.

## Function: `_shared/macros.ts`
`computeMacros(ingredients, servings)` returns `{ per_serving, total }`, where each is:
```json
{ "kcal": 520, "protein_g": 38, "carbs_g": 41, "fat_g": 22,
  "fiber_g": 6, "sugar_g": 9, "sodium_mg": 840,
  "estimated": false, "coverage": 0.97 }
```

## Steps
1. **Convert to grams** for each ingredient:
   | Unit | Conversion |
   |---|---|
   | g, kg, oz, lb | Fixed factors |
   | ml, l, tsp (5 ml), tbsp (15 ml), cup (240 ml) | × `density_g_per_ml`, or 1.0 if missing → mark estimated |
   | each, bunch, pack | × `grams_per_unit`; if missing → can't convert |
   | pinch, "to taste" | 0.5 g / 0 g |
2. **Nutrients:** `grams / 100 × nutrients_per_100g`.
   - **Catalog** ingredients use `catalog.ingredient_nutrients`.
   - **Custom** ingredients use `ingredients_private.nutrients_per_100g`. If that's null, call `estimateNutrition` (F0.5) once and store the result. The macros are then marked `estimated`.
   - **Free text** with no ID: search the catalog once (score ≥ 0.6). If nothing matches, the ingredient isn't counted.
3. **Optional** ingredients (`is_optional`) aren't counted.
4. **Coverage:** grams with real data ÷ total grams. `estimated = true` if coverage < 0.9 or any value was estimated.
5. **Totals and per serving:** per serving = total ÷ servings. Round kcal to the nearest 10 and grams to whole numbers for display. Store the unrounded values.

## Endpoint
`POST /recompute-macros` with `{ recipe_id }`. It loads the recipe's ingredients, recalculates, and updates `macros_per_serving` and `macros_total`. F3.2 calls it after an edit.

## UI rules
- When `estimated` is true, show an "≈" prefix and the footnote "Some values estimated".
- Always show the footnote "Nutrition is approximate."

## Implementation notes (2026-11-08)
Approved during review:
- **Densities** added for 106 foods recipes measure in cups or spoons (dairy, cheese, produce, herbs, frozen, nuts, canned). Values come from USDA household measures ("1 cup = X g", our cup = 240 ml); the source of each is in `supabase/seed/densities.csv` (a few marked "approx"). Meat, fish and snacks are left out: recipes give those by weight or piece. `catalog_test.sql` checks the covered categories.
- **Gram hint:** recipe generation (F2.2) also returns an estimated weight per ingredient, stored in `recipe_ingredients.grams`. It's used only when we can't convert ourselves (a count with no `grams_per_unit`, a volume with no density, or an unknown unit like "clove"), and marks the result estimated. F3.2 must clear or rescale `grams` when an edit changes the amount or unit.
- **Units** accept common spellings ("tablespoons", "cups", "lbs"). Count words other than each/bunch/pack ("clove", "can", "slice") use only the gram hint.
- **Coverage:** an ingredient that can't be converted at all counts as estimated; an ingredient with a weight but no nutrition data lowers coverage.
- **Estimate access:** `recompute-macros` works for every signed-in user. The nutrition estimate (`kind = 'estimate'`, Haiku, low effort) only runs when AI is on and the user has a subscription; otherwise the custom item counts as "no data".
- Code: `_shared/macros.ts` (maths + loading via a store interface), `_shared/nutrition.ts` (Supabase store + estimator), `recompute-macros/`. Tests: `_shared/macros_test.ts` (in `test.sh fn`) and `scripts/test-macros.sh` (live, one estimate call).

## Acceptance criteria
- [ ] Test fixtures, by hand: 200 g chicken breast + 100 g rice matches the USDA-derived values within 1%.
- [ ] Unit conversions are covered by tests, including density and per-unit cases.
- [ ] A custom item with null nutrition triggers exactly one estimate call. The second time, the stored value is used.
- [ ] `recompute-macros` updates the stored values after an edit.
