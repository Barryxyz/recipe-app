# F0.2 Auth & sessions

**Phase** 0 · **Size** M · **Prototype** anonymous sign-in only · **Requirements** NFR-1, NFR-7 · **Depends on** F0.1, F0.3

## Summary
Every user has an account from their first launch, without a sign-up screen. They start anonymous and can upgrade to Sign in with Apple, which keeps the session across reinstalls and devices.

## User stories
- As a new user, I can start using the app immediately, without creating an account.
- As a returning user, I'm still signed in after closing the app or restarting the phone.
- As a user, I can link Sign in with Apple so I don't lose my data if I reinstall or switch phones.
- As a user, I can delete my account and all my data from inside the app.

## Behavior
1. **First launch:** call `signInAnonymously()`. A database trigger on `auth.users` insert creates the `app.households` row, the `app.users` row and default `app.user_prefs`. In v1, the app then sends proof of purchase (F0.6).
2. **Session storage:** the Supabase SDK keeps the session in the Keychain and refreshes tokens automatically. On launch, restore the session; if there isn't one, go back to step 1.
3. **Upgrade (v1):** Settings → "Sign in with Apple" uses `linkIdentity` to attach the Apple identity to the existing anonymous user, so the user id stays the same and no data moves.
   - If that Apple ID already belongs to a different account, offer "Switch to that account". The current anonymous data is discarded, after a confirmation that says so.
4. **Reinstall:** a user linked to Apple signs in with Apple and gets their data back. An anonymous user may lose their data, because the Keychain isn't guaranteed to survive a reinstall. Settings shows a banner: "Sign in with Apple to keep your data safe."
5. **Sign out:** available only for users linked to Apple. Anonymous users see "Delete account" instead, because signing out would orphan their data.
6. **Delete account:** a `delete-account` Edge Function, running with the service role:
   1. Deletes all `app` rows for the user, and the household if no one else is in it. This also clears every `share_token`, which revokes share links.
   2. Revokes the Sign in with Apple token through Apple's REST endpoint (App Store requirement).
   3. Deletes the `auth.users` row.

   The app then wipes its local cache and returns to first launch.

## Data & API
- Trigger: `auth.users` insert → `app.handle_new_user()`.
- Edge Function: `delete-account` (POST, requires the user's JWT).

## Acceptance criteria
- [ ] A fresh install reaches the pantry screen with no sign-in UI, and a user row exists.
- [ ] Killing and relaunching the app keeps the same user id.
- [ ] Linking Apple keeps the same user id and all existing data.
- [ ] After deleting and reinstalling the app, Sign in with Apple restores the data.
- [ ] Delete account removes every row for that user (checked with a SQL query) and makes their share links return 404.

## Edge cases
- No network on first launch: show an offline screen with Retry. The app can't create a user without the server.
- Token refresh fails because the account was deleted on another device: send the user to first launch.

## Out of scope (prototype)
Sign in with Apple, sign out and account deletion. These need the paid developer program, or aren't needed with a single tester.
