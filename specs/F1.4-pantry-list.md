# F1.4 Pantry list

**Phase** 1 · **Size** M · **Prototype** yes · **Requirements** FR-4, FR-11 · **Depends on** F0.3, F1.6

## Summary
The home screen. It shows everything on hand, grouped by location, with the soonest-expiring items first.

## Screen
- **Tabs:** All / Fridge / Freezer / Pantry (segmented control), each with a count.
- **Sort:** `expires_at` ascending. Items with no expiry go last. Alternate sort: A–Z.
- **Row:** name, quantity and unit ("some" when null), and an expiry badge:
  | Badge | Rule |
  |---|---|
  | Red "Expired" | `expires_at` < today |
  | Orange "Today" / "Tomorrow" | Expires within 1 day |
  | Yellow "3 days" | Expires within 3 days |
  | None | Later dates appear as grey text ("Nov 20") |
- **Expired section** *(added 2026-11-04 after device testing)*: shown at the top only when something has expired, on "All" and on each location tab. **Discard all** in the header asks for confirmation, marks every expired item discarded in one request, and can be undone. Items can also be swiped one at a time, or tapped to change the date if they're still good. Expired batches are split from fresh batches of the same ingredient, so Discard all never touches a fresh one.
- **Use these first:** a collapsible block on "All" with the orange and yellow items (today to 3 days). Expired items aren't in it.
- **Grouped batches** *(added 2026-11-04)*: the same ingredient in the same location shows as one row ("Milk ×2", total amount when units match, earliest batch's badge). Tap to expand; a swipe on the collapsed row acts on the earliest batch.
- **Seasonings & Staples** *(added 2026-11-04, user request)*: its own place, not a location. It's the last section of "All" (checked least) and never appears on the Fridge/Freezer/Pantry tabs or in their counts. Staples are pantry items with `is_staple` (the stored location is hidden); amount and expiry are optional (default "some" and none). A dated staple that expires moves to Expired like any item. A–Z.
- **Search ranking** *(added 2026-11-04)*: exact name matches first, then names starting with the text, then names containing it.
- **Search:** filters by name across all locations.
- **Row actions:**
  - Swipe left: reveals **Used** (`status = used`) and **Discard** (`status = discarded`) side by side. A full swipe marks the item used. *(Changed 2026-11-04 after device testing: one swipe with labelled buttons instead of a direction per action.)*
  - Both show an undo toast for 5 s.
  - Tap opens the edit sheet (F1.5).
- **Toolbar:** **Scan** (F1.1), **+** (F1.5), **Recipes** (F2.1). *(Prototype: + and a sort menu now; Scan and Recipes join when those features ship.)*
- **Empty state:** "Your pantry is empty", with two equal buttons, **Scan your fridge** and **Add manually**.

## Data
- Query: `pantry_items` where `status = 'active'`, scoped by RLS.
- Refreshes on appear, on pull-to-refresh and after any add, edit or scan save.
- Prototype reads directly from Supabase. v1 reads from the SwiftData cache (F3.6).

## Acceptance criteria
- [x] Items are sorted by expiry with correct badges. Badge boundaries use the device's local date. *(Unit tests incl. midnight edges + device.)*
- [x] Tabs filter correctly, and the counts match.
- [x] Used and Discard remove the row, and Undo restores it.
- [x] The Expired section appears only when something has expired; Discard all discards exactly those items and can be undone.
- [ ] The empty state shows both entry methods equally. *(Only "Add manually" until scanning ships in F1.1; recheck then.)*
- [x] Handles 300 items smoothly (lazy list). *(Device, 2026-11-04: 313 items.)*
