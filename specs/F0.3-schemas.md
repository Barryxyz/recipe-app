# F0.3 Schemas

**Phase** 0 · **Size** M · **Prototype** yes (without the 50-recipe trigger) · **Requirements** NFR-4, D1 · **Depends on** F0.1

## Summary
Create the `catalog` and `app` schemas from DESIGN §5 as migrations, with row-level security so users only ever see their own household's data.

## Scope
- **Migrations** in `supabase/migrations/`, one per logical change. `pg_trgm` is enabled.
- **Exposed schemas:** add `app` and `catalog` to the API's exposed schemas in Supabase config.
- **Grants:**
  - `catalog`: `select` for `authenticated`. Writes only by the service role or migrations.
  - `app`: `select/insert/update/delete` for `authenticated`, restricted by RLS policies.
- **Helper:** `app.current_household_id()` (security definer, stable) returns the caller's `household_id` from `app.users`.
- **RLS policies:**
  | Table | Rule |
  |---|---|
  | `users`, `user_prefs`, `user_shelf_life_overrides`, `ingredients_private`, `recipes`, `ai_usage_log` | `user_id = auth.uid()` (`id` on `users`). `ai_usage_log` is insert-only and service role only. |
  | `pantry_items`, `shopping_list_items` | `household_id = app.current_household_id()` |
  | `recipe_ingredients` | Parent recipe passes the `recipes` rule (`exists` subquery) |
  | `households` | `id = app.current_household_id()`, read-only |
- **Defaults:** `id` columns default to `gen_random_uuid()`, but the client may supply its own UUIDs (needed for offline creation in F3.6). Timestamps default to `now()`.
- **Indexes:**
  - `pantry_items (household_id, status, expires_at)`
  - `recipes (user_id, updated_at desc)`
  - `recipes (share_token)`, unique
  - `shopping_list_items (household_id, checked)`
  - GIN trigram indexes on `catalog.ingredients.name` and `aliases`
- **50-recipe trigger (v1):** a `before insert` trigger on `recipes` raises error code `P0001` with message `recipe_limit_reached` when the user already has 50 or more recipes where `deleted_at is null`.
- **Purchase columns:** `app.users.purchase_verified_at` and `purchase_environment` can only be updated by the service role (column-level grant), so clients can't mark themselves verified (F0.6).
- **`updated_at` trigger:** on every table that has an `updated_at` column.

## Schema additions (decided 2026-08-05, now in DESIGN §5)
Each is explained in the feature spec listed.
| Change | Why | Spec |
|---|---|---|
| `catalog.ingredients.allergens text[]` | The recipe validator can't detect allergens without tags | F1.7, F2.2 |
| `updated_at` on all synced tables. `deleted_at` (soft delete) on `pantry_items`, `shopping_list_items`, `recipes`, `ingredients_private`, `user_shelf_life_overrides` | Incremental sync and tombstones | F3.6 |
| `user_shelf_life_overrides` primary key gains `location` | Expiry defaults per location | F1.6 |
| `app.users.purchase_verified_at`, `purchase_environment` | AI access only for verified purchases | F0.6 |
| `recipes.source` gains `'shared'` | Tells saved copies apart from originals | F4.3 |
| `recipes.source` gains `'manual'`; `model_version` null for those | User-written recipes | F3.7 |

## Implementation notes (2026-11-03)
- `app.users` has no client write grants at all (stricter than the column grant above): a writable `household_id` would let a user join another household.
- `app.ingredients_private.id` starts at 1,000,000,000,000 so soft-referenced `ingredient_id`s never collide with catalog ids.
- `ai_usage_log.kind` is free text so test calls can be logged (F0.5).
- `user_id` and `household_id` default to the signed-in user and their household.

## Acceptance criteria
- [x] `supabase db reset` builds both schemas from scratch with no errors. *(Prototype: verified with `supabase db push` to the empty hosted project, 2026-11-03; no Docker.)*
- [x] RLS test script (`supabase/tests/rls_test.sql`), with two users A and B: B can't select, update or delete any of A's `app` rows; B can read `catalog`; B can't write `catalog`.
- [ ] Inserting a 51st recipe fails with `recipe_limit_reached` (v1). *(Not in the prototype.)*
- [x] Deleting a recipe cascades to its `recipe_ingredients` rows.
