# F4.3 Universal Links & "Save to my recipes"

**Phase** 4 · **Size** M · **Prototype** no (needs the paid Apple Developer Program) · **Requirements** FR-8 · **Depends on** F4.1, F4.2, F3.1

## Summary
When the recipient has the app, a share link opens the recipe in the app instead of the browser, with a button to save a copy.

## Setup
- **Associated Domains** entitlement: `applinks:<share-domain>`.
- The AASA file (served by F4.2) has `{"applinks":{"details":[{"appIDs":["<TEAMID>.<bundle id>"],"components":[{"/":"/r/*"}]}]}}`.

## In-app behavior
1. The app receives the URL in `onOpenURL` and pulls out the token.
2. It calls `get_shared_recipe(token)`. 404 shows "This recipe is no longer shared."
3. A **shared recipe preview** opens: the F2.4 detail layout with a "Shared recipe" label, and pantry availability marks based on the recipient's own pantry.
4. Actions:
   - **Save to my recipes:** copies the recipe through `save_recipe`, with `source = 'shared'` (new allowed value, see F0.3). It keeps `model_version`, and recalculates macros from the recipient's catalog view.
   - **Add missing to shopping list** (F3.5)
   - **Cooked this** (F3.4)
5. If the recipient owns the recipe, open their saved recipe directly.
6. A first launch from a link runs onboarding first and then opens the recipe. The URL is kept until onboarding finishes.

## Acceptance criteria
- [ ] Tapping a link in Messages with the app installed opens the app, not Safari.
- [x] Save to my recipes creates an independent copy. Later edits by the owner don't change it.
- [x] The saved copy counts toward the recipient's recipe limit. (The 50-recipe limit and replace flow were dropped with the subscription model, F3.1; `save_recipe` enforces the 1,000 safety cap for copies too.)
- [x] Opening your own recipe's link opens the saved recipe.
- [ ] A link opened on a fresh install survives onboarding. (Built: the token is kept on disk until onboarding finishes. Check on the first TestFlight install.)

## Implementation notes (2026-11-14)
- `SharedRecipe.swift`: the `get_shared_recipe` shape, `asRecipe(pantry:)` (marks by name: shared recipes carry no catalog ids), `draft` for the copy, `SharedLink.token(from:)` (only `https://<share host>/r/<22 base62>` and the test scheme), `SharedLinkRouter` (pending token in UserDefaults).
- `SharedRecipeView.swift`: loading / no longer shared / offline / own recipe (matched by `share_token` in the user's list) / preview. Save uses `RecipeCreator.save(draft, source: "shared")` (links ingredients to the recipient's catalog, custom ingredients otherwise), then `recompute-macros`. The Save toggle undoes by soft-deleting the copy.
- `RootView`: `.onOpenURL`; the sheet opens only after the onboarding decision.
- No server change was needed. `shared_recipe_opened` event added. "Shared" tag in the list.
