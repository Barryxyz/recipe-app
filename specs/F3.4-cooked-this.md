# F3.4 "Cooked this"

**Phase** 3 · **Size** M · **Prototype** yes · **Requirements** FR-11 · **Depends on** F1.4, F2.4 / F3.1

## Summary
After cooking, the user confirms what they used, and the pantry is reduced to match. This keeps the inventory accurate without editing items one by one.

## Flow
1. **Cooked this** on a recipe, saved or not, opens the review sheet.
2. **Servings cooked:** a stepper, defaulting to the recipe's servings. Changing it scales the amounts.
3. **One row per recipe ingredient:**
   | Case | Default action |
   |---|---|
   | Matches one active pantry item | **Subtract** the recipe amount, converted to the item's unit, with the result shown: "Eggs: 6 → 4" |
   | Matches several pantry items (e.g. two batches of eggs) | Subtract from the soonest-expiring first, then the next |
   | Pantry item quantity is "some" | Choice: **Used it up** / **Still have some** (default) |
   | Units can't be converted | Show the recipe amount and a field for the new pantry amount |
   | Staple | **Skip** (shown greyed out, can be turned on) |
   | Missing or not in the pantry | Hidden |

   Each row can be changed to: Subtract (with an editable amount) / Used it up / Skip.
4. **Apply:** RPC `app.apply_cooked(changes jsonb)` runs in one transaction. An item whose quantity reaches ≤ 0 gets `status = 'used'`.
5. **Toast:** "Pantry updated · Undo". Undo for 5 s reverses the changes, using a snapshot of the item rows taken before the change.

## Matching recipe ingredients to pantry items
- Match by `ingredient_id`, active items only.
- For an unsaved recipe, use the `pantry_item_id` from generation if that item still exists.

## Implementation notes (2026-11-09)
Approved during review:
- **Conversion:** within weight (g, kg, oz, lb) and volume (ml, l, tsp, tbsp, cup), and between weight, volume and pieces through the catalog's `grams_per_unit` and `density_g_per_ml` (as in F2.3). The recipe's gram estimate is the fallback. Rows that still don't convert ask "Set what's left".
- **Matching:** the item the recipe was generated from (`pantry_item_id`) first, then by catalog id, then by name ("limes" = "lime"). Unexpired items are used before expired ones, soonest expiry first. Each pantry item belongs to one row only.
- **Defaults:** optional ingredients are skipped too (like staples), since they may not have been used.
- **Leftovers** are rounded (g / ml / oz whole, kg / l / lb to 0.01, the rest to ¼); 0 or less marks the item `used`.
- **Button:** a full-width **Cooked this** under the steps, on AI results and saved recipes. "Times cooked" history is out of scope.
- **Database:** `app.apply_cooked(changes)` returns a snapshot of the rows before the change; `app.undo_cooked(snapshot)` restores them. Items no longer active (e.g. used by a household member meanwhile) are skipped.
- Code: `CookedThis.swift` (logic), `CookedThisView`, `Services/CookedAPI.swift`, `RecipeDetailView`; tests: `CookedThisTests`, `supabase/tests/apply_cooked_test.sql`.

## Acceptance criteria
- [ ] A recipe that uses 2 of 6 eggs leaves 4 eggs.
- [ ] Using all of an item marks it `used`, and it disappears from the pantry list.
- [ ] Unit conversion works (recipe asks for 200 g, pantry has 0.5 kg → 0.3 kg).
- [ ] Staples aren't subtracted unless the user turns them on.
- [ ] Undo restores the exact previous quantities and statuses.
