# F1.5 Manual add & edit

**Phase** 1 · **Size** M · **Prototype** yes · **Requirements** FR-13, FR-3, FR-11 · **Depends on** F0.4 (search), F1.6 · **Design** §6.1b

## Summary
A full alternative to scanning. The user adds ingredients by searching the catalog or typing free text, one at a time or several in a row. The same form also edits existing pantry items. It makes no AI calls.

## User stories
- As a user without a fridge photo handy, I can add "2 eggs" in a few taps.
- As a user unpacking groceries, I can add many items in a row without the sheet closing.
- As a user, I can add something the app doesn't know ("grandma's chili") as a custom item.
- As a user, I can fix the quantity, unit, location or expiry of any pantry item.

## Add sheet
**Entry points:**
- **+** on the pantry screen
- "Add manually" on the empty pantry screen
- **Add item** on scan review (F1.3), where it adds to the review list instead of saving
- "Add manually instead" from camera and offline errors (F1.1)

**Layout (bottom sheet):**
```
┌─────────────────────────────────────┐
│ 🔍 Search ingredients…              │
│ Recent: eggs · milk · spinach · …   │  ← chips, shown before typing
├─────────────────────────────────────┤
│ Eggs                     [ - 6 + ] each ▾ │
│ Location  [Fridge|Freezer|Pantry]   │
│ Expires   Nov 23  (edit)            │
├─────────────────────────────────────┤
│ [ Add & next ]          [ Done ]    │
└─────────────────────────────────────┘
```

**Behavior:**
1. **Typing:** debounced at 200 ms, then calls `catalog.search_ingredients(q, 8)`. Results show category icons. The last row is always **Add "<text>" as custom item**.
2. **Recent and frequent chips:** the 10 most recently added `ingredient_id`s for the household, deduplicated. Available offline from the cache in v1.
3. **Picking an item** fills in:
   - unit: the catalog `default_unit`
   - quantity: 1
   - location: from the category (dairy/produce/meat → fridge; frozen → freezer; dry goods/condiments → pantry), or the location last used in this session
4. **Quantity:** a stepper (steps of 1 for `each`, 50 for g and ml) plus a text field. A **some** toggle sets quantity to null.
5. **Units:** each, g, kg, ml, l, oz, lb, cup, tbsp, tsp, bunch, pack.
6. **Expiry:** calculated by F1.6 and shown live. Tapping it opens a date picker. Changing it sets `expiry_overridden`, and the picker offers **Always use N days for <ingredient>**, which writes `user_shelf_life_overrides` (F1.6).
7. **Add & next:** saves the item with `source = 'manual'`, clears the search field, keeps the location, and shows an "Added eggs" tick plus a running count ("3 added").
8. **Done:** saves the current item if it's valid, then closes.
9. **Custom item:**
   - Creates an `ingredients_private` row with `nutrients_per_100g = null`.
   - Defaults: unit `each`, location fridge, expiry 7 days (freezer 90, pantry 30).
   - Later searches for that name return the existing custom item first, so it isn't duplicated.

## Edit sheet
- The same form, filled in, opened by tapping a pantry row.
- Extra actions: **Mark used**, **Discard**, **Delete** (removes the row entirely; meant for mistakes).
- **Partial use:** lower the quantity. If it reaches 0, offer to mark the item used.
- **Changing location** recalculates expiry, unless the expiry was overridden.

## Acceptance criteria
- [ ] A user can add a catalog item in ≤ 3 taps after typing (pick → Add or Done).
- [ ] Adding 10 items with **Add & next** never closes the sheet, and every item is saved with `source = 'manual'`.
- [ ] Custom items are created once and found again in later searches.
- [ ] Search results appear within 300 ms of the last keystroke on a normal connection.
- [ ] No AI call is made (`ai_usage_log` is unchanged).
- [ ] The edit sheet changes are saved, and Used/Discard set `status`.
- [ ] v1: adding works offline, and items sync later (F3.6).

## Out of scope
Natural-language quick add and voice entry (backlog 7), barcode scanning.
