# F2.4 Recipe results UI

**Phase** 2 · **Size** M · **Prototype** yes · **Requirements** FR-5, FR-6 · **Depends on** F2.2 · **Next** F3.1, F3.4, F3.5

## Summary
Shows the 2–3 generated recipes as cards, with a detail view for each, and actions to save, regenerate, cook or add missing items to the shopping list.

## Loading state
- A full-screen loader with rotating status lines ("Checking what's expiring…", "Writing recipes…"). Typically 8–20 s.
- **Cancel** returns to the options sheet.
- On error: `validation_failed` shows "Couldn't come up with good recipes." with the one-tap fixes below. `ai_failed` shows **Retry**.

## Fewer or no recipes (change 2026-11-09)
F2.2 may return fewer recipes, or none, with a `note` and `limited_by` (see F2.2 "never force a recipe").
- **Some recipes + note:** the note is shown above the cards in a small info box.
- **No recipes:** instead of cards, show the note (or "Your pantry doesn't make a good recipe with these options.") and **one-tap fixes** for each option that was limiting, each rerunning F2.2 with that option relaxed:
  - **Allow a few missing items** (when `only_on_hand` was on)
  - **Any time** (when a max time was set)
  - **Any cuisine** (when one was picked)
  - **Any meal** (when a meal was picked)
  - plus **Change options** (back to F2.1) and, when `pantry` is a limit, **Scan** / **Add items**.
- Fixes for options the user didn't set are hidden; diets and allergens are never offered as fixes.

## Results (horizontal paging cards, or a vertical list)
Each card shows:
- title and one-line description
- ⏱ total time
- 🔥 kcal per serving, with P/C/F grams
- a "Uses 2 expiring items" chip, highlighted when there are any
- "Missing: 2 items" if there are missing ingredients

**Footer:** **Regenerate** reruns F2.2 with the same options and replaces the results after confirming "Replace these recipes?". **Change options** goes back to F2.1.

## Detail view
- **Header:** title, description, servings, prep and cook times.
- **Macros strip:** per serving, with a Total toggle and the "≈" rules from F2.3.
- **Ingredients:** quantity, unit, name and note.
  - ✓ green = from the pantry
  - ○ grey = staple
  - ⚠ amber "Missing" = needs to be bought
  - Optional items are in italics.
- **Steps:** numbered and large enough to read while cooking. The screen stays on while this view is open (`isIdleTimerDisabled`).
- **Footer:** a food-safety disclaimer: "AI-generated. Check that meat, poultry, fish and eggs reach safe temperatures."
- **Actions:**
  - **Save** (F3.1)
  - **Add missing to shopping list** (F3.5)
  - **Cooked this** (F3.4)
  - **Share** (v1, only after saving; F4.1)

## State
Results are kept in memory and in a local file until the next generation, so leaving and coming back doesn't lose them. They aren't stored on the server until saved.

## Acceptance criteria
- [ ] 1–3 cards render with time, kcal, expiring and missing info, and the model's note when there is one.
- [ ] No recipes shows the note and the one-tap fixes for the limiting options only.
- [ ] The detail view marks every ingredient as pantry, staple or missing.
- [ ] The disclaimer is always visible in the detail view of AI recipes (`ai`, `edited`, `shared`). It isn't shown on the user's own recipes (`manual`, F3.7).
- [ ] Leaving and coming back to results keeps them. Regenerate asks before replacing.
- [ ] Save, Add missing and Cooked this work from an unsaved recipe.
