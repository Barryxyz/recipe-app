# F0.6 Subscription verification

**Phase** 0 · **Size** M · **Prototype** no (`REQUIRE_PURCHASE=false`) · **Requirements** NFR-8, D5 · **Depends on** F0.2, F0.3, F0.5 · **Rewritten** 2026-11-04 for the subscription model (was: one-time purchase proof)

## Summary
The app is free; photo scanning and AI recipes need a monthly or yearly subscription (D5). The Supabase key in the app is public, so the server, not the app, decides who may call the AI functions: it keeps each account's subscription expiry, updated from Apple-signed data.

## Products
Two auto-renewable subscriptions in one subscription group: **monthly** and **yearly** (starting prices to test: $2.99 and $19.99). Optional introductory free trial. Family Sharing on or off per product (DESIGN §12).

## Flow
1. **Paywall:** a free user tapping Scan or Recipes sees what the subscription includes, both prices, **Restore purchases**, and links to terms and privacy. Purchases use StoreKit 2 (`Product.purchase()`); "Manage subscription" opens Apple's sheet.
2. **App → server:** after a purchase, a restore, and on launch while the server's record is missing or expired, the app sends the signed transaction (`jwsRepresentation`) from `Transaction.currentEntitlements` to `POST /verify-subscription`.
3. **Server checks:** the JWS signature chain against Apple's root certificates using Apple's App Store Server Library (no hand-rolled checks); `bundleId`; product id in the group; `environment` (`Production` or `Sandbox`; Sandbox is what TestFlight and **App Review** use, so prod must accept it; `Xcode` only when `ALLOW_XCODE=true`). The transaction's `appAccountToken` is set to the user's id at purchase, so a transaction can't be replayed onto another account.
4. **On success:** store `subscription_product`, `subscription_expires_at`, `subscription_environment` and the `original_transaction_id` on `app.users`. Service-role only (column grants), so clients can't grant themselves access.
5. **App Store Server Notifications V2** (renewals, expiry, grace period, refunds, revocation) hit `POST /appstore-notifications`, verified the same way, and update the expiry. This keeps access correct without the app being opened.
6. **AI functions** accept an account while `subscription_expires_at > now()` (plus Apple's grace period); otherwise **402 `subscription_required`**, and the app shows the paywall. Non-AI features never check it.
7. **Config:** `REQUIRE_PURCHASE=false` turns enforcement off (prototype and local dev).

## Scan limits (NFR-9)
Independent of the subscription: `scan-ingredients` counts the user's successful scans from `ai_usage_log` (local day and month) against `SCAN_DAILY_LIMIT` / `SCAN_MONTHLY_LIMIT` (defaults 10 and 60) and returns **429 `limit_reached`** with when it resets. Built in the prototype already (2026-11-04).

## Failure handling
- **Offline, or proof not available yet:** retry on the next launch and when the user first taps an AI feature. Pantry, manual entry, saved recipes and the shopping list keep working.
- **AI buttons while unverified:** they show "Checking your subscription…" with **Retry**; without a subscription they open the paywall.
- **Proof still missing:** **Restore purchases** calls `AppStore.sync()`, which may ask the user to sign in to their Apple ID. It's only called when the user taps it.

## Data
`app.users`: add `subscription_product text`, `subscription_expires_at timestamptz`, `subscription_environment text`, `original_transaction_id text` (service role only). `purchase_verified_at` / `purchase_environment` from the one-time model are replaced.

## Acceptance criteria
- [ ] An account created with `curl` and the public key gets 402 `subscription_required` from the AI functions.
- [ ] A TestFlight subscription (Sandbox) is accepted by prod; Xcode transactions are rejected in prod.
- [ ] A user can't write the subscription columns through the API (RLS and column-grant test).
- [ ] Expiry, renewal and refund notifications update access without the app being opened.
- [ ] A transaction from one account can't unlock another (appAccountToken check).
- [ ] No subscription never blocks a non-AI feature.
- [ ] The scan limit returns 429 with the reset time; failed scans don't count.
> Check StoreKit 2 subscription APIs, App Store Server Notifications V2 and the App Store Server Library against Apple's current docs when building this.
