# F1.3 Scan review

**Phase** 1 · **Size** M · **Prototype** yes · **Requirements** FR-3, FR-4 · **Depends on** F1.2, F1.5 (add sheet), F1.6

## Summary
A required step between detection and the pantry. The user confirms, fixes or removes detected items and adds any the scan missed. Nothing reaches the pantry until the user taps **Save**.

## Screen
- **Header:** "Found 14 items in your Fridge", with the location changeable for the whole batch.
- **Rows:** grouped by category. Each row shows the name, quantity and unit, and the expiry date it will get (e.g. "exp. Nov 9").
  - Low-confidence rows have an amber "Check this" tag and sort to the top of their group.
  - Unmatched rows have a "Custom item" tag.
  - Items already in the pantry at the same location show a subtle hint: "You already have 6 eggs here".
- **Row actions:**
  - Tap opens an inline editor: name (re-searches the catalog), quantity stepper or "some", unit picker, location, expiry.
  - Swipe deletes. **Delete all low-confidence** is available in the header menu.
- **Add item** opens the manual add sheet (F1.5) in "add to review list" mode.
- **Footer:** **Save 14 items** (primary) and **Discard** (asks for confirmation).

## Save
1. Unmatched names become `ingredients_private` rows (`nutrients_per_100g = null`).
2. All rows are inserted into `pantry_items` with `source = 'scan'` in one request (one RPC `app.add_pantry_items(jsonb)`, run as a transaction).
3. Expiry comes from F1.6, unless the user changed it in the review (`expiry_overridden = true`).
4. Items already in the pantry become **separate rows**, not merged, because each batch has its own expiry date.
5. Go to the pantry list, scrolled to the location, with the toast "14 items added".

## Draft persistence
The review list (just the JSON, never photos) is saved locally until the user saves or discards. If the app is killed, the next launch offers "Finish reviewing your last scan?".

## Analytics (feeds the accuracy check)
Log per scan: items detected, deleted, edited, added by hand and saved (F5.2). The edit rate is the best real-world measure of scan accuracy.

## Acceptance criteria
- [ ] Every detected item can be edited, deleted or kept. Items can be added.
- [ ] Save writes every row in one transaction. On failure, nothing is written and the draft stays.
- [ ] Low-confidence and custom items are visibly flagged.
- [ ] Expiry dates shown before saving match what is saved.
- [ ] A killed app can resume the review draft.

## Edge cases
- 0 items detected: "Didn't spot any food" with **Retake** and **Add manually**.
- The user deletes every row: the Save button becomes **Discard scan**.

## Addition (2026-11-04)
**Already in your pantry:** a detected item whose `ingredient_id` matches an active pantry item in the same place gets a note ("Already have: milk, 1 l, expires Nov 8") with a choice to skip it, add it as another batch, or update the existing item's amount. Needed because a scan is capped at 2 photos, so a big fridge takes two scans and duplicates across scans aren't merged; it also catches re-scanning a shelf scanned earlier.

## As built (2026-11-04)
- Rows are edited in the same sheet as manual add/edit (F1.5) in a review mode: changes stay in the list until **Save**. **Add item** uses the add sheet in review mode.
- Suggested staples (spices, the 13 common staples) start in **Staples**; scanning with Staples selected puts every row there.
- "Already have" defaults to **Add as another batch**; **Update the amount** replaces the existing amount with the scanned one; **Skip** leaves it out. A different location (or staple vs. not) isn't a duplicate.
- Save: `app.add_pantry_items(items jsonb)`, one transaction (custom items via `get_or_create_custom_ingredient`, inserts with `source = 'scan'`, amount updates). Test: `supabase/tests/scan_save_test.sql`.
- Draft: the review (JSON, never photos) is kept in UserDefaults and offered on the next launch ("Finish reviewing your last scan?").
- Analytics counts (deleted/edited/added per scan) move to F5.2.
- Scan limits (NFR-9) shown on the camera screen ("8 scans left today") and enforced by `scan-ingredients` (429 `limit_reached`); failed scans don't count (`ai_usage_log.ok`).
- Freezer scans tell the model about frost and unlabelled bags, so it prefers broader names with low confidence.
