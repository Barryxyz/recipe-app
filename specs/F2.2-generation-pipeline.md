# F2.2 Recipe generation pipeline (`generate-recipes`)

**Phase** 2 · **Size** L · **Prototype** yes · **Requirements** FR-5, FR-6, FR-12 · **Depends on** F0.5, F1.7, F2.1, F2.3

## Summary
An Edge Function that turns the pantry plus the user's options into 2–3 validated recipes. Ingredients are tied to pantry items, measurements are real, macros are calculated on the server, and the user's allergens never appear.

## API
`POST /generate-recipes` takes the F2.1 request and returns:
```jsonc
{ "recipes": [{
    "temp_id": "r1",
    "title": "...", "description": "...",
    "servings": 2, "prep_min": 10, "cook_min": 20,
    "ingredients": [{
      "position": 1, "name": "spinach",
      "ingredient_id": 41, "pantry_item_id": "uuid|null",
      "kind": "pantry|staple|missing",
      "quantity": 200, "unit": "g", "grams": 200,
      "note": "roughly chopped", "is_optional": false
    }],
    "steps": ["...", "..."],
    "macros_per_serving": {...}, "macros_total": {...},    // from F2.3
    "uses_expiring": ["spinach", "chicken thighs"],
    "model_version": "claude-haiku-5-5"
}]}
```
The response is not saved. Results are temporary until the user taps Save (F3.1).

## Pipeline
1. **Load context:**
   - active pantry items, minus excluded ones, each with name, `pantry_item_id`, quantity, unit, location and days until expiry
   - staples
   - prefs: diets and allergens
   - catalog unit data for those ingredients
2. **Build the prompt:**
   - The pantry is a compact table with IDs.
   - Expiring items (≤ 3 days) are marked when `prefer_expiring` is on.
   - **Hard rules:**
     - Use only listed IDs, staples, or ingredients marked `missing`.
     - Use at most 3 missing ingredients per recipe, or none when `only_on_hand` is set.
     - Never use the listed allergens.
     - Follow the selected diets.
     - Stay within `max_minutes`.
     - Give metric or common kitchen units.
     - Include safe internal temperatures for meat, poultry, fish and eggs.
     - Don't calculate nutrition.
   - Return 3 recipes that differ from each other (not three stir-fries).
3. **Call** `RECIPE_MODEL` with the output schema (F0.5).
4. **Validate** each recipe. A recipe that fails is removed, not fixed:
   | Check | Rule |
   |---|---|
   | Schema | All required fields present. Steps not empty. 1 ≤ servings ≤ 12. |
   | References | Every `pantry_item_id` exists in the context, and every staple is in the staples list |
   | Quantities | Converted to grams (F2.3 unit table), the amount used is ≤ the amount on hand × 1.1. Skipped when either side is "some" or can't be converted. |
   | Allergens | No ingredient's `catalog.allergens` overlaps the user's allergens. Name match for free text and custom items. |
   | Time | `prep + cook` ≤ `max_minutes` + 5 |
   | Missing | ≤ 3 missing ingredients, or 0 when `only_on_hand` is set |
5. **Fallback:** if fewer than 2 recipes pass, call `FALLBACK_MODEL` once with the same prompt (D3) and validate again. If still fewer than 1 passes, return `validation_failed`.
6. **Macros:** for each surviving recipe, calculate them with F2.3.
7. **Return** up to 3 recipes.

## Quality evaluation (prototype)
- A fixed set of 5 pantries × 3 option sets, run with `eval/recipe_eval.ts`.
- Report how often recipes pass validation and how often fallback was needed.
- Rate 15 recipes by hand from 1 to 5. **Target:** average ≥ 4, fallback rate < 15%. **Met 2026-11-11: 4.87, fallback 0%.**

### Results (2026-11-11)
`python3 -I scripts/eval-recipes.py` (15 requests, previous titles sent along as in the app):
- **Run 1:** 42 recipes, fallback 1/15 (7%), median 14.0 s, p90 19.1 s. Issues found: the same first dish for every option set, strawberry-glazed cod in the odd pantry, garlic as "2 each".
- **Fixes:** prompt rules for variety (different main ingredient, method and kind of dish; real dishes of the chosen cuisine), no odd pairings to use something up, garlic in cloves; the app sends the last ideas' titles (`avoid_titles`) so new requests suggest other dishes.
- **Run 2:** 36 recipes (2 instead of a weak third in 6 of 15 requests, each with a note), fallback 0/15, median 15.8 s, p90 20.9 s.
- **Hand rating (run 2, first recipe of each request):** 14 × 5 and one 3 (Baja-style cod tacos with strawberry salsa, odd pantry): **average 4.87**. Target met (≥ 4, fallback < 15%).

## Acceptance criteria
- [ ] Returns 2–3 recipes in under 20 s at p90 (Haiku path). *(2026-11-11 quality eval, 15 requests each: run 1 median 14.0 s, p90 19.1 s; run 2 (variety and pairing rules, recent titles) median 15.8 s, p90 20.9 s. Borderline.)*
- [x] An allergen added to prefs never appears in 50 generated recipes. This is a test, with both allergen-tagged and name-matched ingredients. *(unit tests with hidden-allergen cases + 26 live recipes with milk, peanut and soy allergies: none)*
- [x] Quantities used never exceed what's on hand by more than 10%, where convertible.
- [x] With `only_on_hand`, no returned recipe has a missing ingredient.
- [x] A forced validation failure triggers exactly one fallback call. *(recipes_test.ts)*
- [x] Each model call is logged with `kind = 'recipes'` (fallback calls: `recipes_fallback`).
- [x] Every recipe has times, measured ingredients, steps and macros (FR-6).

## Note (2026-11-04)
Staples are now pantry items (`pantry_items.is_staple`, F1.7 change), so "available ingredients" is simply every active pantry item; `user_prefs.staple_ingredient_ids` is deprecated. Staple items usually have no quantity ("some"), so treat them as always sufficient.

## Note (2026-11-08, from F2.3)
Each returned ingredient also carries `grams`: the model's estimate of its weight. It's stored in `recipe_ingredients.grams` and used by the macros calculator only when the amount can't be converted from catalog data (F2.3).

## Change (2026-11-09): never force a recipe
Approved after F2.1 review. Odd or thin pantries must not produce odd recipes.
1. **Prompt:** "Only combine ingredients that genuinely go well together. Recipes don't need to use every item. Return fewer recipes (even none) rather than a strange or forced one." This replaces "Return 3 recipes" in step 2.
2. **Output:** the model may return 0–3 recipes plus an optional `note` explaining what limited it (e.g. "Your pantry has no main ingredient; these need 2 things from the store." or "With only these items I can't make a proper meal."), and `limited_by`: any of `only_on_hand`, `max_minutes`, `cuisine`, `meal`, `diet`, `pantry`.
3. **Validation and fallback:** returning fewer recipes **with a note** is a valid answer, not a failure. The fallback model (step 5) runs only when recipes were returned but too few passed the checks, never because the model chose to return fewer. An answer of 0 recipes returns 200 with `{ recipes: [], note, limited_by }` (no second model call).
4. **API:** the response gains `note` (string|null) and `limited_by` (string[]).
5. **Expired items** (past `expires_at`) are never sent to the model, matching the F2.1 sheet ("2 expired items left out").
6. **Eval:** add an "odd pantry" case (e.g. ketchup, strawberries, frozen fish, oat milk) to the eval set, with and without `only_on_hand`. Pass = no forced combinations in the hand rating; returning fewer recipes with a sensible note is a pass.

## Implementation notes (2026-11-09)
Approved during review:
- **Limits:** 20 recipe requests per user per local day and 300 per month (`RECIPE_DAILY_LIMIT`, `RECIPE_MONTHLY_LIMIT`), checked like scans (`app.ai_usage(kind)`); 429 `limit_reached` when used up. `{ check: true }` returns the usage. A request counts once: the primary call logs `kind = 'recipes'`, the fallback logs `kind = 'recipes_fallback'`.
- **Pantry refs:** the prompt gives rows short ids (`P1…` pantry, `S1…` staples) instead of UUIDs; the server maps them back to `pantry_item_id`. Up to 150 pantry rows (soonest expiry first) and 80 staples.
- **Allergen and diet checks** are in code (`_shared/food_rules.ts`): catalog tags OR name words, with look-alikes removed ("coconut milk", "oyster mushrooms", "nutmeg") and hidden sources added (pesto, Worcestershire, soy sauce, mayonnaise, satay). Custom allergies match their own word. Diets enforced in code: vegetarian, vegan, pescatarian, dairy-free, gluten-free, halal (pork, alcohol), kosher (pork, shellfish); keto and low-carb are prompt-only.
- **Quantity check** compares in the same unit, or in grams when both sides convert exactly (F2.3); skipped otherwise. Uses of the same item within a recipe add up.
- **Fallback** (`runPipeline`): runs when a call fails or when returned recipes fail the checks and fewer than 2 pass; the answer with the most passing recipes wins. Zero recipes with a note is final.
- **Allergen test:** the 50-recipe live run is replaced by unit tests with hidden-allergen cases (`food_rules_test.ts`, `recipes_test.ts`) plus a live run (`scripts/test-recipes.py`, 7 requests) with milk, peanut and soy allergies and a pantry of cheddar, milk, peanut butter and soy sauce. The forced-validation-failure criterion is covered by `recipes_test.ts` (fake model calls).
- Response also includes `attempts` (model, passed/returned, drop reasons) and `usage`.
- **Tuning (2026-11-09, after the first live run):** `RECIPE_EFFORT` is `low` (median 21.6 s → 17.0 s, max 20.8 s; all checks still passed). The prompt aims for 3 recipes and only returns fewer when the pantry or options can't support them; the note only says what the user could change and never repeats allergies or diets. Measured: about 2,000 input and 3,800 output tokens per request.
