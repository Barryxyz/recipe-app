# F3.1 Save & list recipes

**Phase** 3 · **Size** M · **Prototype** yes (without the 50 limit) · **Requirements** FR-7 · **Depends on** F0.3, F2.4

## Summary
Turns a generated recipe into a saved one, and gives the user a searchable list of up to 50 saved recipes.

## Save
- **Save** on a generated recipe calls the RPC `app.save_recipe(recipe jsonb)`. In one transaction, it inserts the `recipes` row (`source = 'ai'`, `model_version`) and its `recipe_ingredients` rows. It returns the new `id`.
- `pantry_item_id` isn't stored, because pantry items change. `ingredient_id`, `name`, `quantity`, `unit` and `grams` are copied.
- The button changes to **Saved ✓** and links to the saved recipe.
- Saving the same generated recipe twice is blocked on the client: the button is disabled once saved.

## 50-recipe limit (v1)
- The database trigger raises `recipe_limit_reached` (F0.3).
- The app shows the **Replace a recipe** sheet: saved recipes, oldest first, each with a radio button. **Replace & save** deletes the chosen recipe and saves the new one in one RPC (`app.replace_and_save_recipe(old_id, recipe)`).
- The recipes tab header shows the count ("37 / 50") once the user has 40 or more.

## Recipes tab
- **List:** sorted by `updated_at` descending. Each row shows title, total time and kcal per serving, plus an "Edited" tag if `source = 'edited'` or a "Mine" tag if `source = 'manual'`.
- **Search:** on the client, over title and ingredient names. Fine at 50 recipes.
- **Filter chips:** Can make now (all non-optional ingredients on hand), Under 30 min.
  - "Can make now" compares the recipe's `ingredient_id`s with active pantry items and staples. Quantities aren't compared, only presence.
- **Tap** opens the same detail view as F2.4, with Edit, Delete and Share added.
- **Empty state:** "No saved recipes yet", with **Generate recipes** and **Write your own** (F3.7).
- **+** in the toolbar: **New recipe** (F3.7).

## Implementation notes (2026-11-09)
Approved during review:
- **No 50-recipe limit** (subscription model): no replace sheet and no "37 / 50" header. `app.save_recipe` keeps a safety cap of 1,000 saved recipes (`recipe_limit_reached`).
- **Save** is a toolbar button on the detail view of a generated recipe; it becomes **Saved ✓**, and the result card shows a "Saved" tag. Saved ids are kept with the local results (`RecipeSession.savedIds`), so reopening "Your last ideas" can't save the same recipe twice.
- **Can make now** matches by catalog id, then by name ("lime" = "limes"); expired items don't count; staples do. Saved recipes' detail view marks ingredients pantry / staple / missing against the pantry as it is now.
- **Not yet:** "Write your own" and **+** (F3.7), Edit (F3.2), Share (F4.1).
- Code: migration `20261109110000_save_recipe.sql`, `Services/SavedRecipesAPI.swift`, `Features/Recipes/SavedRecipe.swift`, `RecipesView`; tests: `save_recipe_test.sql`, `SavedRecipeTests`.
