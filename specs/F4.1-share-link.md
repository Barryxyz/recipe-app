# F4.1 Share link

**Phase** 4 · **Size** S · **Prototype** no · **Requirements** FR-8 · **Depends on** F3.1 · **Next** F4.2, F4.3

## Summary
The owner of a saved recipe can create a link that anyone can open, and can revoke it later.

## Behavior
1. **Share** on a saved recipe calls the RPC `app.create_share_link(recipe_id)`.
   - If `share_token` is null, it generates a token: 16 random bytes, base62-encoded (~22 characters). Otherwise it returns the existing token.
   - It returns `https://<share-domain>/r/<token>`.
2. The iOS share sheet opens with the URL and the text "<title>: a recipe from <App>".
3. The recipe's ⋯ menu shows **Stop sharing** when it's shared. That clears `share_token` (after a confirmation), and the old link returns 404. Sharing again creates a **new** token.
4. Shared recipes show a link icon in the list.

## What the link shows
The page renders the recipe **as currently saved**, so the owner's edits appear on it. The recipient gets a fixed copy only when they tap **Save to my recipes** (F4.3).

> DESIGN §6.5 says "snapshot". This spec reads it as "the recipient saves a snapshot", which avoids storing a second copy of every shared recipe. If you want the page itself frozen at share time, add a `share_snapshot jsonb` column instead.

## Security
- Tokens can't be guessed (128 bits), and recipes are only reachable through `app.get_shared_recipe(token)`, a security-definer function that returns recipe fields only (no user id or other data).
- No list endpoint and no lookup by recipe id.

## Acceptance criteria
- [ ] Sharing twice returns the same link. After revoking and sharing again, the link is new.
- [ ] A revoked or deleted recipe's link returns 404.
- [ ] `get_shared_recipe` exposes no owner information.
