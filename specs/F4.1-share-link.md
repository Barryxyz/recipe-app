# F4.1 Share link

**Phase** 4 · **Size** S · **Prototype** no · **Requirements** FR-8 · **Depends on** F3.1 · **Next** F4.2, F4.3

## Summary
The owner of a saved recipe can create a link that anyone can open, and can revoke it later.

## Behavior
1. **Share** on a saved recipe calls the RPC `app.create_share_link(recipe_id)`.
   - If `share_token` is null, it generates a token: 16 random bytes, base62-encoded (~22 characters). Otherwise it returns the existing token.
   - It returns `https://<share-domain>/r/<token>`.
2. The iOS share sheet opens with the URL and the text "<title>: a recipe from <App>".
3. The recipe's ⋯ menu shows **Stop sharing** when it's shared. That clears `share_token` (after a confirmation), and the old link returns 404. Sharing again creates a **new** token.
4. Shared recipes show a link icon in the list.

## What the link shows
The page renders the recipe **as currently saved**, so the owner's edits appear on it. The recipient gets a fixed copy only when they tap **Save to my recipes** (F4.3).

Decided 2026-08-05 (DESIGN §6.5): the page shows the live recipe, and the recipient's saved copy is the snapshot.

## Security
- Tokens can't be guessed (128 bits), and recipes are only reachable through `app.get_shared_recipe(token)`, a security-definer function that returns recipe fields only (no user id or other data).
- No list endpoint and no lookup by recipe id.

## Implementation notes (2026-11-11)
- Database: `app.create_share_link(p_recipe_id)` (security definer, owner only; 22 base62 characters from 22 random bytes), `app.stop_sharing(p_recipe_id)`, and the public read `public.get_shared_recipe(p_token)`, which lives in the `public` schema so the anon key needs no access to the `app` schema. It returns title, description, servings, times, steps, macros, `is_ai` and ingredients (name, amount, unit, note, optional): no ids, owner, token or dates.
- App: **Share** (toolbar) on saved recipes opens the share sheet with "<title>: a recipe from Fridge" and the link; **Stop sharing** in the ⋯ menu after a confirmation; a link icon in the list. Needs internet. Logs `share_created` (F5.2).
- The link's base is `SHARE_BASE_URL` in `ios/Config/*.xcconfig` (the Worker's workers.dev address).
- Tests: `supabase/tests/share_links_test.sql`.

## Acceptance criteria
*(`share_links_test.sql`, and an end-to-end check against the live page on 2026-11-13.)*
- [x] Sharing twice returns the same link. After revoking and sharing again, the link is new.
- [x] A revoked or deleted recipe's link returns 404.
- [x] `get_shared_recipe` exposes no owner information.
