# F4.2 Public recipe page

**Phase** 4 · **Size** M · **Prototype** no · **Requirements** FR-8 · **Depends on** F4.1

## Summary
A read-only web page at `https://<share-domain>/r/<token>`, so people without the app can see a shared recipe.

## Hosting (D6)
DESIGN §4 has `share-page` as a Supabase Edge Function. Two catches:
1. Supabase serves Edge Function HTML on the default `*.supabase.co` domain as plain text (**check against current Supabase docs**), so a custom domain is needed.
2. Universal Links (F4.3) need an `apple-app-site-association` file on that same domain. Supabase custom domains are a paid add-on.

**Decision:** buy a domain (~$10–15/year) and host the page on **Cloudflare Workers** (free tier). The Worker:
- serves `/.well-known/apple-app-site-association`
- serves `/privacy` (F5.3)
- for `/r/:token`: calls `get_shared_recipe` through the Supabase REST API with the anon key, then renders HTML

The `share-page` function from DESIGN §4 then isn't needed.

## Page
- **Content:** title, description, servings, times, macros per serving, ingredients and numbered steps.
- **Footer:** the food-safety disclaimer (AI recipes only; manual recipes say "Shared by its author" instead), and "Made with <App>".
- **Design:** mobile-first, a single column of plain HTML and CSS, no JavaScript needed, and light and dark mode.
- **Head tags:**
  - Open Graph tags (`og:title`, `og:description`, `og:image` as a static app image) for iMessage and WhatsApp previews.
  - `<meta name="robots" content="noindex">`
  - Smart App Banner (shows the free App Store listing): `<meta name="apple-itunes-app" content="app-id=…, app-argument=<url>">`
- **Not found** (revoked, deleted or bad token): a friendly 404 page, "This recipe is no longer shared."
- **Caching:** `Cache-Control: public, max-age=60`, so revoking takes effect within about a minute.

## Implementation notes (2026-11-11)
- Confirmed: Supabase rewrites HTML from Edge Functions to text/plain on the default domain (custom domains only, and not meant for web pages), so the page is a **Cloudflare Worker** (`share/`), on the free `*.workers.dev` address for now: **https://fridge-share.fridge-app.workers.dev** (a custom domain can be added later; links already shared would keep the old address).
- `share/src/render.js` (page HTML, no JavaScript, light / dark), `share/src/index.js` (routes: `/r/<token>`, `/.well-known/apple-app-site-association`, everything else 404). Malformed tokens never reach Supabase; Supabase errors give a 502 that isn't cached. Headers: `Cache-Control: public, max-age=60`, `X-Robots-Tag: noindex`, a strict CSP.
- The footer has the food-safety line (AI recipes) or "Shared by its author", plus the allergy warning (as in F4.4). No app name anywhere on the page until the name is final (change 2026-11-13: "Made with Fridge" removed).
- **Not yet:** the Smart App Banner (needs an App Store id, F5.3), `og:image` (needs a static image), `/privacy` (F5.3).
- Tests: `share/test/worker_test.js` (`deno test share/test`, also in `./scripts/test.sh fn`). Deploy: `./scripts/deploy-share.sh` (one-time `./scripts/deploy-share.sh login`; Node 18+ from `~/.local/node22`).

## Acceptance criteria
- [ ] The link opens on desktop and mobile Safari and Chrome without the app installed, and shows the full recipe.
- [ ] Pasting the link in iMessage shows a preview with the title.
- [x] A revoked token shows the 404 page within 60 s. *(live check: 404 right after Stop sharing)*
- [x] The page doesn't appear in search engines (noindex) and shows no owner information.
